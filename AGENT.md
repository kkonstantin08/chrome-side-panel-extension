# Project instructions

Before making any frontend or UI changes, read `design.md`.

Treat `design.md` as the source of truth for:

- visual style
- layout
- typography
- colors
- spacing
- animations
- components
- responsive behavior

Do not create generic Tailwind/shadcn/SaaS-looking design if it conflicts with `design.md`.

When implementing UI:

1. First inspect the existing project structure.
2. Read `design.md`.
3. Extract concrete design rules from it.
4. Implement the UI according to those rules.
5. Reuse existing components where possible.
6. After implementation, compare the result against `design.md` and fix mismatches.

If something is missing in `design.md`, make the smallest reasonable assumption and write it in the final response.
